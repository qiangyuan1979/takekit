# TakeKit 实施计划

- 日期：2026-09-29
- 依据：[设计规格](../specs/2026-09-29-takekit-design.md)
- 技术栈：Tauri 2 + React + TypeScript + Zustand + Rust
- 工作目录：`e:\trae solo\takekit`

---

## 里程碑总览

| # | 里程碑 | 内容 | 验收标准 |
|---|--------|------|----------|
| M1 | 工程骨架 + 立项 | Tauri 2 工程、步骤条框架、项目文件夹与 `project.json` 原子读写、密钥存储、**立项**环节 | `npm run tauri dev` 打开 TakeKit；新建项目 → 填完立项 → 关闭重开字段还原；导出 `project.json` 结构正确 |
| M2 | 剧本 | 双栏对话、剧本四段字段、LLM 适配器（OpenAI 兼容）、AI 生成/续写/重写、字段锁 | 无 Key 时「模板填充」可走通；有 Key 时 AI 结果落到右栏且锁定字段不被覆盖 |
| M3 | 资产 | 角色/场景/道具卡、参考图上传、画风锁定、三视图/定妆照生成（图片适配器） | 建 2 个角色并生成定妆照；重启后资产与图片仍在；剧本角色占位能双向补全 |
| M4 | 分镜 | 按场拆镜（AI + 规则兜底）、表格/卡片双视图、下拉字典、时长校验 | 一集拆出 ≥10 镜；时长累计正确；超出单集时长有提示 |
| M5 | 关键帧 | 首/尾帧生成、4 候选挑选定稿、参考图注入、跨镜参考、外部上传 | 同一角色在两镜的首帧风格一致；跨镜参考生效 |
| M6 | 出题 | 统一提示词模型、参数层、适配器翻译、提示词体检、复制与导出 | 同一分镜产出两家模型各自可用的请求体；导出的 CSV 往返无损 |
| M7 | 生成 | 任务队列、抽卡与择优、版本归档、审核失败建议、成本预估 | 一次提交 5 镜、1 镜失败也能重试至全部有产物；片段按 `镜号_版本` 归档 |
| M8 | 横向收口 | 模板库、新手引导、导入导出与交接包、素材库、设置、项目管理 | 全新用户按引导走完一遍并成功导出交接包 |
| v1.5 | 后期出片 | TTS、对口型、字幕、BGM、四轨拼接、导出预设 | 一段 3 镜的分镜能导出可发布的竖屏成片 |

**v1 必须**：M1–M7。M8 若工期紧张，可裁剪到「模板库 + 设置」，其余顺延。

## 各阶段任务分解

### M1 · 工程骨架 + 立项

**目标**：跑起来、能存盘、立项可用。

**开工清单（文件级）**

```
takekit/
  package.json / vite.config.ts / tsconfig.json
  eslint.config.js / .prettierrc.json / rustfmt.toml
  src/
    main.tsx, App.tsx, index.css
    state/store.ts            # Zustand：project / ui / steps
    lib/ipc.ts                # invoke 封装 + 错误归一化
    lib/types.ts              # 与 Rust 结构镜像
    i18n.ts
    components/
      AppShell.tsx            # 顶部栏 + 步骤条 + 环节容器 + 底部导航
      StepRail.tsx            # 8 步 + 状态 + 后期灰态
      StepGuard.tsx           # 下一步阻塞清单
      panels/ProjectPanel.tsx # 立项四卡
      CollapsibleCard.tsx
      FieldRow.tsx            # 字段 + 锁定图标 + AI 三动作 + 「为什么这么设」
  src-tauri/
    src/
      main.rs, lib.rs
      error.rs                # AppError 分类 + 可读消息
      secrets.rs              # 密钥存储（系统凭据库，降级本地加密文件）
      project/
        mod.rs                # Project 模型 + schemaVersion
        store.rs              # 原子写 + 备份滚动
        migrate.rs            # schema 迁移
      commands/
        project.rs            # create / open / save / list_recent / duplicate
        settings.rs
    tests/
      project_roundtrip.rs
      atomic_write.rs
      migrate.rs
```

**任务**

- [ ] 初始化 Tauri 2 工程（Vite + React + TS 模板），目录 `e:\trae solo\takekit`
- [ ] 接入 ESLint + Prettier + rustfmt，沿用 PDF 项目规范（`printWidth: 100`、`max_width = 100`）
- [ ] 借鉴现有 PDF 项目的既有形态实现 `state/store.ts`、`lib/ipc.ts`、`i18n.ts`（减少重复摸索）
- [ ] `error.rs`：`AppError` 分类（IO / Serde / Network / Auth / Provider / Validation）+ 前端可读消息
- [ ] 数据模型：`Project / Meta / Episode / Scene / Shot / Frame / Assets / Character / SceneAsset / Prop / StyleLock / Task / TemplateRef`，Rust serde 结构 + TS 类型镜像 + 契约测试
- [ ] `project/store.rs`：`project.json` 原子写（临时文件 → rename）+ 滚动备份（保留 N 份）
- [ ] `project/migrate.rs`：`schemaVersion` 迁移框架（v1 起）+ 迁移前自动备份
- [ ] `commands/project.rs`：新建 / 打开 / 保存 / 最近项目 / 复制项目
- [ ] `secrets.rs`：密钥存储（决策点 3 默认策略：系统凭据库 → 失败降级本地加密文件）
- [ ] `AppShell` + `StepRail`：8 步步骤条，状态为 未开始 / 进行中 / 已完成 / 有阻塞，第 8 步「后期」灰态
- [ ] `StepGuard`：进入下一步时校验前置字段，缺失则列出清单并禁用下一步
- [ ] 立项环节：四张折叠卡（作品定位 / 规格参数 / 风格锚点 / 生成默认配置）
- [ ] 条件字段：`类型 = 短视频` 时隐藏「集数」等短剧字段
- [ ] 推荐值默认选中 + 每字段一句「为什么这么设」说明
- [ ] 双栏骨架（左栏占位"AI 共创"，M2 接入 LLM）
- [ ] 立项参数继承机制：`meta` 暴露给后续环节的模板注入接口（先定接口，M2 起使用）

**测试**

- [ ] Rust 单测：`project.json` round-trip（含全部字段）；原子写在模拟中断下不产生半截文件；备份滚动保留数与淘汰顺序
- [ ] Rust 单测：schema 迁移（构造旧版本样本 → 迁移 → 字段完整）+ 迁移前备份存在
- [ ] 前端单测：立项字段写入 store；条件字段渲染；`StepGuard` 阻塞清单
- [ ] E2E：新建项目 → 填立项 → 关闭 → 重开 → 字段还原

**验收**：`npm run tauri dev` 可新建项目、走完立项、重开还原；`cargo test` 与 `vitest` 全绿。

### M2 · 剧本

**目标**：左栏聊、右栏成型；AI 结果落到结构化字段。

**任务**

- [ ] LLM 适配器：`src-tauri/src/adapters/llm/mod.rs`（`trait LlmProvider`）+ `openai_compat.rs`
- [ ] LLM 设置项：`base_url` / `api_key` / `model` / 温度 / 最大长度；Key 走 `secrets.rs`
- [ ] 流式输出与超时/限流分支；错误归一化为可读提示
- [ ] 左栏 `ChatPanel`：消息流、快捷指令（"按模板写大纲""续写这场""重写成悬疑风"）
- [ ] 右栏剧本四段：A 创意核 / B 大纲 / C 剧本正文（按场）/ D 一致性引用
- [ ] 结构模板内置（短剧：铺垫→冲突升级→反转→大结局；短视频：3 秒钩子→冲突→反转→CTA）
- [ ] 字段级 AI 三动作：生成 / 续写 / 按模板重写；结果只写右栏
- [ ] 字段锁：锁定字段在 AI 重写时不覆盖
- [ ] 右栏 → 左栏上下文同步（AI 始终知道当前设定）
- [ ] 「场」的增删改与排序
- [ ] 角色占位与待补清单（未在第 3 步定义的角色在此列出）
- [ ] 纯文本粘贴导入（决策点 11：文件解析归 v1.5）

**测试**

- [ ] mock LLM（固定响应）驱动全链路；流式与非流式各一例
- [ ] 超时 / 限流 / 返回非法 JSON 三条失败分支
- [ ] 字段锁：锁定的 logline 经「按模板重写」后不变
- [ ] 前端单测：右栏编辑后左栏上下文同步；场排序与增删

**验收**：无 Key 时能用「模板填充」走完剧本；有 Key 时 AI 生成可用且结果全部落在右栏字段。

### M3 · 资产

**目标**：角色不换脸，场景不漂移。

**任务**

- [ ] `ImageProvider` trait + 即梦适配器（决策点 1 默认；参考图能力不足则改用 Seedream）
- [ ] 角色卡 CRUD：ID / 名字别名 / 年龄性别 / 外貌 / 服装（多套）/ 性格与说话风格 / 音色
- [ ] 场景卡 CRUD：ID / 名称 / 室内外 / 时间天气 / 环境描述 / 光线
- [ ] 道具卡 CRUD：ID / 名称 / 描述
- [ ] 参考图上传与存储（`assets/characters|scenes|props/`），前端经 asset 协议回显
- [ ] 画风锁定：全局风格提示词 + 风格参考图 + 固定种子
- [ ] 三视图/定妆照生成：4 候选 → 挑选 → 指定基准（决策点 5：默认取第一张，可手动指定）
- [ ] 与剧本 D 段角色占位的双向补全 + 待办清空校验
- [ ] 角色「服装套装」切换（同一角色多套造型分别出图，保持脸部一致）

**测试**

- [ ] mock 图片 provider：候选生成、挑选、定稿落盘
- [ ] 参考图文件命名与路径稳定性；删除角色时的引用清理
- [ ] 剧本占位 → 资产补全的闭环测试

**验收**：建 2 个角色、各生成定妆照，重启后资产与图片俱在，剧本占位全部消解。

### M4 · 分镜

**目标**：把场拆成镜，并守住总时长。

**任务**

- [ ] 「按场拆镜」：AI 产出候选镜头列表，可增删改
- [ ] 规则兜底（决策点 7）：无 AI 时按"一镜一场"确定性拆分，保证流程可推进
- [ ] 镜头字段：镜号 / 所属集场 / 景别 / 机位与运镜 / 时长 / 画面描述 / 出场角色 / 台词旁白 / 音效提示 / 转场 / 备注
- [ ] 景别、运镜、转场下拉字典（禁自由文本），字典集中定义便于后续扩词
- [ ] 表格视图：虚拟滚动 + 批量编辑（多行同改）
- [ ] 卡片视图：每镜一卡，含缩略图占位与关键字段
- [ ] 时长累计：按集求和，与立项单集时长对比，超标即时提示
- [ ] 按集按需加载（决策点 9），避免整表渲染卡顿
- [ ] 出场角色选择器：从资产的角色卡多选

**测试**

- [ ] 拆镜兜底路径：AI 不可用时仍能拆出可用结果
- [ ] 时长校验边界：恰好等于 / 超 1ms / 严重超标
- [ ] 表格批量编辑后 store 与 `project.json` 一致
- [ ] 大数据量（≥200 镜）渲染与滚动性能

**验收**：一集能拆出 ≥10 镜、时长累计正确、超标有提示、两种视图切换数据一致。

### M5 · 关键帧

**目标**：画面可控，不是抽卡。

**任务**

- [ ] 每镜首帧（必需）+ 尾帧（可选）的生成与定稿
- [ ] 4 候选并排预览 → 挑选 → 局部重绘/微调 → 定稿
- [ ] 参考图注入：优先厂商原生能力；不支持则 Rust 侧本地拼图（决策点 4，用 `image` crate 合成并在 prompt 标注分区）
- [ ] 自动组装 prompt：角色参考图 + 场景参考图 + 画风锚 + 镜头画面描述 + 立项规格
- [ ] 跨镜参考：可指定"以镜头 N 的定稿帧为参考"保证连贯
- [ ] 外部图片上传作为首/尾帧
- [ ] 未定稿首帧的镜头在步骤条标「有阻塞」（联动 M6/M7）

**测试**

- [ ] 本地拼图合成单测（尺寸、分区、边缘）
- [ ] 参考图权重透传正确
- [ ] 跨镜参考链路：B 镜定稿引用 A 镜定稿帧
- [ ] 首帧缺失时阻断下游（步骤条阻塞状态）

**验收**：同一角色在两镜的首帧风格一致，跨镜参考生效。

### M6 · 出题（核心）

**目标**：统一提示词模型 → 各家可用请求体。

**任务**

- [ ] `UnifiedPrompt` 结构体与拼装器：主体（角色引用 + 动作）→ 环境 → 镜头语言 → 光线色调 → 风格 → 画质词
- [ ] 中英文 prompt 同时产出（决策点 10：英文质量不稳时改由 LLM 精修）
- [ ] 参数层：时长 / 画幅 / 分辨率 / 帧率 / 运动强度 / 种子 / 负向提示词 / 参考图及权重 / 首尾帧
- [ ] `VideoProvider` trait + 可灵适配器：字段映射、长度截断、不支持字段的降级提示
- [ ] 第二家视频适配器（即梦）验证适配器抽象是否成立
- [ ] 提示词体检规则集：缺主体 / 缺运镜 / 过长 / 自相矛盾
- [ ] 词条词典（JSON）：每个专业词的"为什么这么写"说明，供悬浮展示
- [ ] 单镜一键复制（中文 prompt / 英文 prompt / 完整参数 JSON）
- [ ] 分镜表导出：CSV / Excel / JSON，双向（导入可覆盖现有分镜）
- [ ] 交接包导出：分镜表 + 提示词包 + 参数表 + 关键帧

**测试**

- [ ] 拼装器黄金用例：完整字段 / 缺角色 / 缺场景 / 缺运镜各一
- [ ] 各 provider 翻译黄金用例（输入统一模型，断言输出请求体）
- [ ] 截断逻辑：超长时高亮被裁部分并提示信息可能丢失
- [ ] 降级提示：模型不支持的字段被请求时给出明确提示
- [ ] 导出往返：导出 CSV → 重新导入 → 数据一致

**验收**：同一分镜可产出可灵与即梦各自可用的请求体；导出的 CSV 往返无损。

### M7 · 生成

**目标**：一键出片段，失败能救。

**任务**

- [ ] Rust 侧任务队列（tokio）：提交、并发上限、指数退避重试、超时、取消
- [ ] 进度事件推送到前端（逐任务状态：排队 / 进行 / 成功 / 失败 / 已取消）
- [ ] 取结果方式：轮询优先（决策点 6），接口限制大时再上回调
- [ ] 抽卡：多种子批量提交，并排预览，标记「采用」
- [ ] 版本归档：`clips/镜号_版本.mp4`，同镜多版本保留与切换
- [ ] 审核失败处理：解析被拦字段 → 换词建议（联动 M6 体检）
- [ ] 成本预估：可获取计费规则时显示预估费用，否则显示 token/秒数（决策点 2）
- [ ] 失败任务不丢：重启应用后未完成任务可恢复查看

**测试**

- [ ] mock HTTP 覆盖：成功 / 超时 / 限流 / 审核失败 / 部分失败
- [ ] 并发上限生效；取消后中间产物被清理
- [ ] 5 镜提交、1 镜失败 → 重试后全部有产物
- [ ] 版本归档命名与「采用」标记持久化

**验收**：一次提交 5 镜、其中 1 镜失败，队列能重试并最终全部有产物且正确归档。

### M8 · 横向收口

**任务**

- [ ] 模板库：题材（如"都市逆袭三幕"）/ 分镜 / 运镜 / 提示词 / 立项预设；存应用数据目录（决策点 8）
- [ ] 新手引导：每步一屏「这步干什么 / 常见错误 / 示例」，可跳过，设置中可关闭
- [ ] 导入导出收口 + 交接包完整性校验（缺关键帧或首帧要报错）
- [ ] 素材库：参考图 / 音频 / 字体，跨项目复用
- [ ] 设置页：模型与 Key、默认参数、界面语言、字体、引导开关
- [ ] 项目管理：新建 / 打开 / 最近 / 复制 / 归档

**测试**

- [ ] 模板套用后字段完整、可继续编辑
- [ ] 交接包完整性校验：故意缺关键帧时导出应失败并指出缺什么
- [ ] 素材跨项目复用（A 项目上传，B 项目可用）
- [ ] E2E：全新用户按引导走完 v1 全流程（mock provider）并导出交接包

**验收**：全新用户按引导走完一遍并成功导出交接包。

### v1.5 · 后期出片

依据 spec §5.8 拆分：

- [ ] TTS 适配器 + 逐句生成（绑定角色卡音色）+ 句↔镜号映射表
- [ ] 对口型（仅正面口型镜头，走同一任务队列）
- [ ] 字幕：由台词旁白生成时间轴 + 逐句微调 + 样式模板 + SRT/ASS 与烧制两种导出
- [ ] BGM 与音效：素材库选曲、情绪基调推荐、对白音量闪避、音效提示挂接
- [ ] 四轨时间线拼接（片段 / 配音 / 字幕 / BGM）+ 转场取自分镜字段
- [ ] 导出预设：抖音/快手/视频号（竖屏 1080×1920）、B站/YouTube（横屏）
- [ ] 不做：多轨调色、复杂特效、多机位同步
