# TakeKit 设计规格（Spec）

- 日期：2026-09-29
- 状态：待评审
- 产品名：TakeKit
- 定位：面向新手小白的**流程式短视频／短剧辅助制作工具**

---

## 1. 目标与成功标准

### 1.1 一句话定义

TakeKit 用一条**线性流程**把短视频／短剧制作从"我有个想法"串到"我拿到了可用的视频片段"，把每个环节需要写的提示词、需要设的参数、需要保持一致的角色与场景，都变成**填空式的结构化操作**，让没做过视频的人跟着走一遍就能出东西，并且走完之后自己也学会了怎么拆解。

### 1.2 成功标准

1. 零经验用户能在不做任何外部学习的情况下，走完流程并产出至少 1 个可用视频片段。
2. 用户走完一遍后，能理解"立项 → 剧本 → 资产 → 分镜 → 关键帧 → 出题 → 生成"各环节的作用，可脱离本工具自行拆解制作。
3. 同一角色在多镜头中视觉一致（由角色卡 + 参考图机制保证），不出现"同一人换个脸"的失败观感。
4. 分镜表、提示词、参数均可导出，不被工具锁定。

### 1.3 非目标（v1 明确不做）

- 不做云端账号体系与多人协作。
- 不做视频剪辑时间线（拼接、转场、调色）——归 v1.5。
- 不做 TTS 配音、对口型、字幕烧制——归 v1.5。
- 不做平台热点抓取与选题推荐——归后续版本。
- 不做移动端。

---

## 2. v1 范围与演进路线

| 阶段 | 范围 | 说明 |
|---|---|---|
| **v1** | 最小闭环 + 一致性资产 + 方法论与素材 | 立项 / 剧本 / 资产 / 分镜 / 关键帧 / 出题 / 生成 + 引导、模板库、导入导出、项目管理、素材库、设置 |
| **v1.5** | 后期出片 | TTS 配音、对口型、字幕、BGM、拼接转场、导出成片 |
| **v2** | 平台化 | Web 端、多设备同步、选题推荐、协作 |

要点：**v1 只做"出提示词 + 参数 + 调 API 生成片段"**，不做成片组装。这是刻意的取舍——先把最难的"出题与一致性"打透，再叠加后期。

## 3. 核心设计原则

1. **流程式向导**：左侧固定步骤条，一次只面对一个环节；每一步可回退、可跳过、有明确完成状态（未开始 / 进行中 / 已完成 / 有阻塞）。
2. **结构化右侧为唯一真相源**：AI 的一切输出只写进结构化字段；聊天记录不参与下游计算。
3. **参数向下继承**：立项里定的画幅、画风、受众、平台、默认模型等，自动注入后续每一步的提示词模板，用户无需重复填写；分镜级可覆盖。
4. **一致性优先**：角色 / 场景 / 道具 / 画风以"卡 + 参考图"形式固化，生成时自动挂载。
5. **不锁定用户**：任何环节的产出都能导出（CSV / Excel / JSON），随时可以离开工具手搓。
6. **教方法，不只给结果**：每个环节内置"这步干什么 / 常见错误 / 示例"，走一遍即是一份方法论。
7. **约束优于自由**：景别、运镜、时长等用下拉与预设，而不是自由文本——新手最需要被约束。

## 4. 交互模型（整体信息架构）

```
┌──────────────────────────────────────────────────────────────┐
│ 顶部栏：项目名 · 保存状态 · 设置 · 导出                        │
├────────────┬─────────────────────────────────────────────────┤
│            │  环节标题 + 「这步干什么 / 常见错误 / 示例」      │
│  步骤条     │  ┌──────────────────┬───────────────────────┐  │
│ 1 立项  ✓  │  │  左栏             │  右栏                  │  │
│ 2 剧本  ●  │  │  AI 共创 / 生成   │  结构化字段表单        │  │
│ 3 资产     │  │  对话与快捷指令   │  （唯一真相源）        │  │
│ 4 分镜     │  │                  │                        │  │
│ 5 关键帧   │  └──────────────────┴───────────────────────┘  │
│ 6 出题     │                                                 │
│ 7 生成     │  ┌───────────────────────────────────────────┐  │
│ 8 后期(灰) │  │ 底部：上一步 / 下一步（带完成校验提示）     │  │
└────────────┴─────────────────────────────────────────────────┘
```

**双栏对照的具体约定**

- 左栏是"对话 + 快捷指令"，右栏是字段表单；**右栏永远是唯一真相源**。
- AI 生成结果直接写入右栏对应字段，可立即手改；改完可回左栏让 AI 按新设定继续。
- 每个字段旁有**锁定图标**：锁定后 AI 重写不覆盖该字段。
- 每个输入框右上角统一三个动作：**AI 生成 / AI 续写 / 按模板重写**。
- 右栏字段变更时，左栏 AI 的上下文同步更新（保证 AI 知道当前设定）。

## 5. 环节设计

### 5.1 步骤 1 · 立项

**本质**：把模糊的喜好收敛成可传递给下游的硬参数。

四个折叠卡片，每张卡的每个字段都有推荐值（默认选中）与一句"为什么这么设"：

| 卡 | 字段 |
|---|---|
| 卡1 作品定位 | 作品名 · 类型（短剧·多集 / 短视频·单条） · 赛道题材（都市逆袭 / 甜宠 / 悬疑 / 知识科普 / 带货…） · 目标平台 · 目标受众画像 |
| 卡2 规格参数 | 画幅（9:16 / 16:9 / 1:1） · 分辨率与帧率 · 单集时长（15s/30s/60s/90s） · 集数（仅"短剧"显示） · 语言与字幕语言 |
| 卡3 风格锚点 | 画风（实拍写实感 / 动漫 / 3D / 国风 / 赛博…） · 情绪基调（爽 / 甜 / 悬疑 / 治愈） · 参考作品或风格关键词 · 可上传参考图作画风锚 |
| 卡4 生成默认配置 | 默认视频模型 · 默认图片模型 · 默认 LLM · 默认配音音色 · 参数预设（全项目继承，分镜级可覆盖） |

**条件字段**：`类型 = 短视频` 时自动隐藏"集数"等短剧字段。同一套数据模型 + 条件渲染，不是两套模板。

**产出**：`Project.meta`，供后续所有环节继承。

---

### 5.2 步骤 2 · 剧本

**本质**：把故事变成结构化的"场"。到此为止不再拆镜——拆镜是步骤 4 的事。

四段，均为"左对话右结构"：

**A. 创意核**：logline（一句话故事） · 核心冲突 · 主角目标与阻碍 · 爽点/钩子设计 · 结尾反转

**B. 大纲**：
- 结构模板：短剧 = 铺垫 → 冲突升级 → 反转 → 大结局；短视频 = 3 秒钩子 → 冲突 → 反转 → CTA
- 分集大纲（短剧）或分段大纲（短视频）
- 每集节拍 beat

**C. 剧本正文**：按**场**组织——场号 · 内/外景 · 地点 · 时间 · 出场角色 · 动作描述 · 对白（含旁白）

**D. 一致性引用**：C 段出现的角色在此挂**角色卡引用位**。此时允许只写占位名，步骤 3 补全外貌细节；存在未定义角色时列出待办。

**产出**：`Episodes → Scenes`，台词与动作字段是步骤 4 拆镜的输入。

---

### 5.3 步骤 3 · 资产（一致性）

**本质**：短剧成败的关键——让人物、环境、画风在多镜头间保持一致。

| 卡片 | 字段 |
|---|---|
| 角色卡 | ID · 名字/别名 · 年龄性别 · 外貌（脸型、发型发色、瞳色、身高体型） · 服装（可多套：日常/职场/礼服） · 性格与说话风格 · 音色（留给 v1.5 TTS） · 参考图（上传或 AI 生成：正/侧/半身/全身） |
| 场景卡 | ID · 名称 · 室内外 · 时间与天气 · 环境描述 · 光线 · 参考图 |
| 道具卡 | ID · 名称 · 描述 · 参考图 |
| 画风锁定 | 全局风格提示词模板 · 风格参考图 · 固定种子 |

**关键机制**

- 每张角色卡可一键生成**三视图 / 定妆照**，作为后续所有镜头的视觉基准。
- 步骤 5、6 生成时，按镜头"出场角色"自动挂载对应参考图与画风锚。
- 与剧本双向联动：剧本 D 段的引用位在此补全。

---

### 5.4 步骤 4 · 分镜

**本质**：把"场"时间轴化为"镜"，并守住总时长。

- **由场自动拆镜**：「按场拆镜」一键操作，AI 给出候选镜头列表，人工增删改（新手不会拆镜，靠此起步）。
- **镜头字段**：镜号 · 所属集/场 · 景别（远/全/中/近/特写） · 机位与运镜（推/拉/摇/移/跟/升降/环绕/固定） · 时长 · 画面描述 · 出场角色（引用角色卡） · 台词/旁白 · 音效提示 · 转场 · 备注
- **景别与运镜一律下拉选项**，不做自由文本。
- **双视图**：表格视图（类 Excel，便于批量修改）／卡片视图（每镜一张大卡，便于看画面）。
- **时长自动累计**，与立项设定的单集时长对比，超标即时提示——新手最常犯的错是分镜拼起来远超时长。

---

### 5.5 步骤 5 · 关键帧

**本质**：让画面可控，而非纯抽卡。

- 每镜产出**首帧（必需）+ 尾帧（可选）**，供图生视频 / 首尾帧生视频使用。
- 生成方式：文生图 / 图生图（自动挂角色参考图 + 场景参考图 + 画风锚）。
- 流程：AI 出 4 张候选 → 挑选 → 局部重绘/微调 → 定稿；也支持从外部上传图片。
- **跨镜连贯**：可指定"以镜头 N 的定稿帧为参考"，保证同场景连续镜头画面不跳。

---

### 5.6 步骤 6 · 出题（核心护城河）

**本质**：新手写不好提示词，就把这一步做成填空式与自动拼装。

**第一层 · 统一提示词模型（结构化 → 段落化）**

按固定结构拼装：

```
主体（角色卡引用 + 动作）
→ 环境（场景卡）
→ 镜头语言（景别 / 运镜）
→ 光线与色调
→ 风格（画风锁定）
→ 画质词
```

同时输出**中文 prompt 与英文 prompt**（部分模型对英文更友好）。

**第二层 · 参数与适配**

- 参数：时长 / 画幅 / 分辨率 / 帧率 / 运动强度 / 种子 / 负向提示词 / 参考图及权重 / 首尾帧。
- **适配器翻译**：把统一提示词模型映射为各家字段（v1 先接可灵、即梦），处理长度截断，并对"该模型不支持此字段"给出降级提示。

**新手辅助**

- 每个词条悬浮显示"为什么这么写"。
- **提示词体检**：缺主体 / 缺运镜 / 过长 / 自相矛盾会报警。

**产出**：可一键复制，也可批量导出。

---

### 5.7 步骤 7 · 生成

**本质**：一键出片段，失败能救。

- **任务队列**：批量提交、并发上限、失败重试、超时处理、可取消。
- **抽卡挑选**：同镜可生成 N 个候选（可指定多个种子），并排预览择优。
- **审核失败处理**：给换词建议，而不是干巴巴报错。
- **版本与归档**：片段按 `镜号_版本` 存入项目文件夹，可标记"采用"。
- **成本预估**：提交前按各模型计费规则估算（能获取价格时显示）。

---

### 5.8 步骤 8 · 后期出片（v1.5，本节为 v1.5 目标设计）

**本质**：把散落的镜头片段组装成可发布的成片。

v1 中该步骤在步骤条上显示为灰态（"即将支持"），不实现功能；以下为 v1.5 的设计目标。

**5.8.1 配音（TTS）**

- 按剧本台词逐句生成，自动读取角色卡「音色」字段——同一角色全片统一音色，这是 v1 建立角色卡音色字段的目的。
- 支持语速、停顿时长、情绪标注；对白与旁白分轨。
- 不满意的句子可单独重生成，不重跑全片。
- 产出：每句一个音频文件 + 「句 ↔ 镜号」映射表（供对口型与字幕使用）。

**5.8.2 对口型**

- 输入：该镜「采用」的片段 + 该句配音；仅在本镜存在角色正面口型时启用，其余镜头跳过。
- 逐镜处理，可批量；走与生成环节相同的任务队列与进度机制。

**5.8.3 字幕**

- 由台词与旁白自动生成时间轴，按镜头时间对齐。
- 支持逐句微调起止时间；样式模板（字体、描边、位置、竖屏安全区）。
- 导出两种形态：软字幕（SRT / ASS）与烧制进画面。

**5.8.4 BGM 与音效**

- 从素材库选曲，按立项卡3 的「情绪基调」推荐。
- 自动音量闪避：对白出现时压低 BGM。
- 分镜的「音效提示」字段可一键挂接素材库音效。

**5.8.5 拼接与转场**

- 按集/镜序自动拼接，转场取自分镜的「转场」字段。
- 时间线视图：片段轨、配音轨、字幕轨、BGM 轨。
- 支持片段替换与重排；时长变化自动重算总长并与立项单集时长复核。

**5.8.6 导出成片**

- 分辨率、帧率、码率取自立项卡2，画幅与立项保持一致。
- 导出预设：抖音/快手/视频号（竖屏 1080×1920）、B站/YouTube（横屏）。
- 导出任务进同一队列，支持后台运行与进度显示。

**与 v1 的衔接**：v1 已产出结构化分镜（含时长、转场、台词、音效提示）、采用片段、关键帧与角色音色——后期环节直接消费这些字段，不需要重新组织数据。

**v1.5 的取舍**：不做多轨调色、不做复杂特效、不做多机位同步；目标只是"新手能出可发布成片"。

## 6. 横向能力

### 6.1 新手引导

每个环节进入时一屏说明："这步干什么 / 常见错误 / 示例"，可一键跳过；可在设置中关闭。走完全流程即等于一份方法论教程。

### 6.2 模板库

- 题材模板（如"都市逆袭三幕"）
- 分镜模板、运镜模板
- 提示词模板
- 立项预设（"抖音竖屏 60s 甜宠短剧"一键套用）

### 6.3 导入导出

- 分镜表 CSV / Excel / JSON **双向**导入导出。
- **交接包导出**：分镜表 + 提示词包 + 参数表 + 关键帧，便于离开工具手搓。

### 6.4 项目管理

一个项目 = 一个文件夹。支持新建、打开、最近项目、复制项目、归档。

### 6.5 素材库

参考图 / 音频 / 字体统一管理，可跨项目复用。

### 6.6 设置

模型与 Key 配置、默认参数、界面语言、字体、引导开关。

## 7. 数据模型

```
Project
 ├─ schemaVersion
 ├─ meta            # 立项参数（画幅/画风/平台/受众/默认模型/参数预设）
 ├─ episodes[]      # 短剧：多集；短视频：退化为单一默认集，结构统一
 │    └─ scenes[]
 │         └─ shots[]
 │              └─ frames[]        # 首/尾帧，含候选与定稿
 ├─ assets
 │    ├─ characters[]  # 含外观、服装、音色、参考图、定妆照
 │    ├─ scenes[]
 │    ├─ props[]
 │    └─ styleLock     # 风格提示词、风格参考图、种子
 ├─ tasks[]         # 生成任务：类型、provider、请求、状态、结果、错误
 ├─ templateRefs[]  # 引用的模板 id（模板本体存全局模板库，不复制进项目）
 └─ exports[]       # 导出历史
```

**Shot 关键字段**

```
id, episodeId, sceneId, no,
shotSize, cameraMove, durationMs,
visualDesc, characters[](assetRef), dialogue, narration,
sfxHint, transition, note,
promptBundle { unified, zh, en, params, perProvider },
adoptedClipId
```

**版本与迁移**：`schemaVersion` 随结构变更递增，启动时对旧项目做迁移；迁移前自动备份。

## 8. 磁盘结构

```
takekit/
  project.json              # 全量结构化数据（唯一真相源）
  assets/
    characters/             # 参考图、定妆照
    scenes/
    props/
    style/
  keyframes/                # 统一或按 shot 分目录
  clips/                    # 镜号_版本.mp4
  exports/                  # 分镜表、提示词包、交接包
  backups/                  # 自动备份
  .takekit/project.lock
```

**写入策略**：`project.json` 采用原子写（写临时文件 → rename），避免崩溃导致数据损坏；每次结构性写入前滚动备份至 `backups/`。

## 9. 技术架构

### 9.1 技术栈

- **前端**：React + TypeScript + Zustand（沿用现有 PDF 项目的技术习惯，降低维护成本）
- **桌面外壳**：Tauri 2
- **后端**：Rust（Tauri commands）
- **数据层抽象**：Repository 接口 —— v1 落地本地 FS 实现，后续直接加远程实现即可上 Web

### 9.2 职责划分

| 层 | 职责 |
|---|---|
| 前端 | 流程向导 UI、双栏交互、结构化表单、分镜表格/卡片视图、AI 对话、进度展示 |
| Rust 后端 | 项目目录与文件读写、原子写与备份、**HTTP 请求（避免前端暴露 API Key、绕开 CORS）**、异步任务队列、图片处理（候选拼图、裁剪、格式转换）、成本估算 |
| 适配器层 | `LlmProvider` / `ImageProvider` / `VideoProvider` 三个 Rust trait，新增一家模型 = 新增一个实现文件 |

### 9.3 模型接入策略

- **LLM**：走 OpenAI 兼容协议，用户填 `base_url + api_key + model`，可对接豆包 / DeepSeek / 通义等。
- **图片模型**：与视频模型同一套适配器思路，v1 先接 1 家（即梦或 Seedream）。
- **视频模型**：v1 先接可灵（Kling）与即梦（Seedance），以图生视频 / 首尾帧生视频为主；其余按适配器接口逐个补。
- **Key 存储**：全部由 Rust 侧持有，前端不接触明文；落本地加密存储（系统凭据库或本地加密文件）。

### 9.4 出题层与适配层解耦

出题层**只产出"统一提示词模型"**，不感知任何厂商字段；由适配器负责翻译、截断与降级。这样新增模型不改出题逻辑，新增出题规则不改适配器。

## 10. 错误处理

| 场景 | 处理 |
|---|---|
| 模型 API 超时 / 限流 / 5xx | 分类提示 + 指数退避重试 + 保留已提交任务不丢 |
| 内容审核失败 | 明确提示被拦字段，给出换词建议（联动提示词体检） |
| Key 无效 / 欠费 / 无权限 | 引导到设置页，指明是账号级还是模型级问题 |
| 网络离线 | 编排全流程（立项～出题、导出）离线可用，仅"生成"需联网，并明确提示 |
| 提示词超长 | 自动裁剪并高亮被裁部分，同时提示可能的信息丢失 |
| 长任务 | 可取消；取消后清理远端/本地中间产物 |
| 项目文件损坏 | 原子写 + 自动备份；启动检测到解析失败时提供"从最近备份恢复" |
| 缺少必需字段（如无首帧就提交视频生成） | 步骤条标"有阻塞"，下一步按钮给出具体缺失清单 |

## 14. 术语表

| 术语 | 含义 |
|---|---|
| 立项 | 确定作品定位、规格、风格与默认模型配置的环节 |
| 场（Scene） | 剧本中同一地点、同一时间的连续剧情单元 |
| 镜（Shot） | 分镜的最小单位，对应一次视频生成 |
| 关键帧 | 镜头首帧/尾帧图像，图生视频的输入 |
| 统一提示词模型 | TakeKit 内部与厂商无关的结构化提示词表示 |
| 适配器 | 把统一提示词模型与参数翻译为具体厂商 API 字段的模块 |
| 交接包 | 导出的分镜表 + 提示词包 + 参数表 + 关键帧集合 |
